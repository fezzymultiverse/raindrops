# Raindrops V1.9.8 - YouTube search sequential (on top of V1.9.7)

## What I found in raindrops-V1_6_0 (the build where YouTube worked)
- That zip is the web layer only (www/ plus launcher icons). It has no Java, so the YouTube engine that worked lived in the APK you installed then, not in this zip. I cannot see or copy it.
- Its JavaScript calls the same plugin methods as today (ytSearch, ytGet, ytClean, ytProgress) with the same result fields, so the V1.9.x plugin matches what the app expects.
- One real difference: V1.6.0 sent ONE search (music_songs, then videos if empty). V1.9.x sent SIX at once (3 wordings x 2 kinds, limit 30). That is a plausible cause of rate-limit errors or a stalled search. UNCONFIRMED.

## IMPLEMENTED
- www/stream.js: searches now run one at a time and stop once 45 results are found. Same result list, same dedupe, same Show more button.
- www/diag.js: Fix + diagnose now also runs the music_songs search V1.6.0 used first.

## MUSIC LOADING: NOT FIXED, cause not found
- The import code in V1.9.x is the V1.6.0 code plus protection (per-file try/catch, pause for the UI, one import at a time). I found no regression there.
- The guards from V1.9.7 (service crash path, renderer-lost guard, in-app log) are the candidates. If it still crashes, Fix + diagnose names the cause.

## TESTED / NOT TESTED
- Tested: node --check on all www/*.js; the new search loop in headless Chromium against a mock plugin (calls are sequential, results draw).
- NOT tested: Java compile, Gradle, real YouTube, any phone.
