# Raindrops V1.9.6 - YouTube plugin, GitLab build, icon wired, crash report (on top of V1.9.5)

## What changed
- NEW native/RaindropsPlugin.java: the missing "Raindrops" plugin. Methods ytSearch, ytGet, ytClean and the ytProgress event, exactly what stream.js and deezer.js call.
- NEW native/YtFetch.java: NewPipe Extractor engine copied from Prodigy Syncing (syncing_V1.zip), repackaged to com.fezzy.raindrops, plus runCache() which downloads the audio into the app cache for ytGet.
- NEW .gitlab-ci.yml: lints, runs prep-android.sh, builds raindrops.apk. Nothing runs in Termux.
- prep-android.sh rewritten in pure bash: icons, manifest, plugins, NewPipe + OkHttp + desugaring in Gradle, version code, cap sync. MainActivity is always regenerated with both plugins registered.
- ICON: android-res/res (the raindrop) is now copied into the build by CI. Before, only prep-android.sh did it and it never ran in CI, so the phone kept the default icon. Default webp icons are removed so they cannot shadow it.
- CRASH REPORT: CrashLog.java saves the last uncaught crash. On the next launch the app copies it to the clipboard and shows a toast. Paste it to me and I fix the exact line.
- package.json: Capacitor 8 -> 6 (^6.2.0, plugins ^6). This matches the Syncing toolchain that already builds on GitLab with JDK 17. package-lock.json removed so CI resolves it fresh.
- NEW scripts/push-gitlab.sh, scripts/setup-signing-gitlab.sh, scripts/newpipe.version, GITLAB.md, LICENSE, NOTICE.md, SECURITY.md (NewPipe Extractor is GPL-3, the app ships GPL-3).

## NOT TESTED
- Java was not compiled and nothing ran on a phone. First CI run is the real test.
- The crash cause is unconfirmed. The crash report above will name it if it happens again.
- Gradle patch tested on a sample Capacitor 6 layout only.
