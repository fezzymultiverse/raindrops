# Raindrops V1.9.7 - build hardening, crash guards, in-app diagnostics (on top of V1.9.6)

## IMPLEMENTED
- .gitlab-ci.yml rewritten: runs on every branch (not only main), lint job cannot block the build, retries for npm, JDK 17 / Node 18 guard, logs (gradle-build.log, prep.log) kept as artifacts even on failure, last 40 Gradle lines printed on failure, APK contents printed after build, optional manual `signing-key` job.
- prep-android.sh: fails the build if the raindrop icon is not in all 5 densities, adaptive, round, monochrome, or if the manifest does not point at it; adds android:icon/roundIcon/largeHeap if missing; Gradle memory raised to 3 GB; checks the NewPipe version exists on JitPack and falls back to older tags; installs RenderGuard only if the real Capacitor source in node_modules has the needed APIs.
- KeepAliveService.java: startForeground is the first thing done with three fallbacks. Before, if both calls failed the service stopped without ever calling startForeground, which makes Android 12+ kill the whole app. Plugin now only starts the service while the app is on screen (Android 12+ forbids it from the background) and only refreshes an already running one otherwise.
- native/optional/RenderGuard.java: when Android kills the WebView renderer (usually low memory) Capacitor lets the whole app die, which looks like a restart. This keeps the app alive, notes the reason in the crash log and rebuilds the screen.
- www/diag.js + Record tab card "Fix + diagnose": records JS errors and your last taps, detects "Android closed the app without a clean exit" (foreground or background), and one button checks YouTube (NewPipe), Deezer, Audius, LRCLIB and Wikipedia with the exact error. Copy report button.
- Text that told you to run prep-android.sh now says to install the newest APK from GitLab CI.

## TESTED (in my sandbox)
- node --check on every www/*.js incl. diag.js; bash -n on every script; .gitlab-ci.yml parses as YAML.
- prep-android.sh run against a mock Capacitor-6-like android/ folder: icon check passes, manifest edits, Gradle edits, NewPipe fallback (a fake curl said only v0.24.8 exists and it picked it), RenderGuard installed into MainActivity.
- index.html loaded in headless Chromium: no page errors, the diagnostics button runs, the unclean-exit note appears after a simulated kill.

## NOT TESTED
- The Java was not compiled and Gradle was not run (no network in my sandbox). The first GitLab run is the real test.
- NewPipe against live YouTube was not tested. The pinned tag v0.26.5 and the fallback tags are not confirmed to exist.
- Nothing ran on a phone. The cause of "adding music crashes" is NOT confirmed: I found no bug in the add-music code itself. The guards above are the likely causes (service crash, renderer killed for memory); if it still happens, Fix + diagnose will say which.
